# 客户端一键更新

在「内网机器 → 机器详情」的「客户端版本」卡片点击「一键更新 Client」。确认后，服务端通过已认证的 TLS 控制连接发送更新请求。客户端检查最新正式 Release，下载匹配本机 Linux 架构的 `opennofrp-client`，原子替换程序，再以原有参数、环境变量和 PID 执行新版本。

升级期间控制流继续接收规则和发送心跳；进程重启时隧道会短暂中断。页面会等待客户端以目标版本重新连接，再显示升级成功。已是最新版本时不会重启。安装失败、重复任务、等待超时、安装后重启失败会显示对应结果；无法确认时不会显示成功。

## 使用条件

- 机器在线，且 Client 支持 `self_update` 能力。
- Client 能访问 GitHub Release 或现有更新镜像。
- Client 进程对当前程序所在目录有写权限。按项目安装脚本部署的 root 服务通常满足这一条件。
- Client 程序所在文件系统可写。只读容器镜像或单文件只读挂载不能原地升级，需要更新容器镜像或挂载来源。

服务端和客户端需要使用包含本功能的构建。此前版本的客户端不认识远程更新指令，按钮会禁用。首次启用时，在机器上升级至包含本功能的发布版本，再重启：

```sh
sudo opennofrp-client update
sudo systemctl restart opennofrp-client
```

在该功能的首个版本尚未发布时，可以部署对应源码构建；仅推送代码不会更新 Releases。后续版本即可在面板一键升级。

## 安全与结果

仅面板管理员登录会话可发起更新，POST 请求需要有效 CSRF 令牌。每台机器同时只允许一个更新任务。控制消息不携带任意下载地址或命令，客户端复用现有官方 Release 更新器，不提供远程 shell。

更新结果是同一控制流上的独立消息，通过随机请求 ID 匹配；它与心跳、规则快照共享串行写入锁，防止消息帧交错。安装后服务端确认收到结果，客户端再执行重启。

如果提示「新版本已安装，但尚未确认重新连接」，检查客户端日志、连接配置和进程状态；新程序已写入磁盘，但不代表正在运行的新版本已得到服务端确认。页面显示的 Client 版本来自当前握手，不使用安装结果替代实际运行版本。
