# 风险评估与回滚方案

## 一、风险等级分类

| 操作 | 风险等级 | 说明 |
|---|---|---|
| 在服务器上传输/编译 OpenNoFrp 二进制文件 | 🟢 低 | 只是文件操作，不影响运行中的服务 |
| 启动 OpenNoFrp Server 监听新端口 | 🟢 低 | 全新端口，不影响现有连接 |
| 注册 systemd 服务（未 enable/start） | 🟢 低 | 只是写配置文件 |
| 启动 systemd 服务 | 🟡 中 | 需确认端口未冲突、进程能正常拉起 |
| 修改 SSH 相关配置 | 🔴 禁止 | 本项目任何阶段都不涉及 |
| 修改 iptables/nftables 规则 | 🔴 禁止 | 本项目任何阶段都不涉及 |
| 修改路由表/网卡配置 | 🔴 禁止 | 本项目任何阶段都不涉及 |
| 卸载脚本执行 | 🟡 中 | 需确保只删除本项目文件，见下方"卸载安全清单" |

## 二、为什么"断了就完了"——具体后果推演

这台服务器目前只有一种管理方式：SSH（root@1，走 frpc 转发的 22222 端口 + 直连 22 端口两条路径）。如果：

- SSH 服务本身崩溃/配置错误 → 除非有物理访问权限或云厂商的 VNC/KVM 控制台，否则**无法登录**
- 网络配置错误导致服务器对外不可达（比如路由表被破坏、网卡被误关闭） → 即使 SSH 服务本身没问题，也**连不上**
- 防火墙规则误封锁了 SSH 端口 → 同样**连不上**

一旦发生上述任一情况，恢复手段只能是：
1. 联系服务器托管方，请求物理/带外访问（如果有的话）
2. 或者干等到某个已配置的自动化任务/开机脚本自我修复（如果提前埋了的话）

**这就是本项目自始至终不碰路由/防火墙/网卡配置的根本原因**——OpenNoFrp 完全运行在应用层，最坏情况下崩溃只会导致自己监听的端口不可用，SSH 通道不受任何影响。

## 三、部署前置检查清单（safety/preflight-check）

每次在服务器上做任何操作前，必须先跑这个只读检查脚本，确认：

1. 当前 SSH 会话工作正常（脚本执行本身就是证明）
2. 目标端口（控制端口 + 数据端口范围）当前未被占用（`ss -tlnp` 核对）
3. 现有 frpc/frpc2/Docker 网络的关键指标记录一份快照（用于事后对比是否被意外影响）
4. 磁盘空间、内存充足（避免因资源不足导致部署失败留下半吊子状态）

只有全部检查通过，才继续下一步。

## 四、Watchdog 自动回滚设计（safety/watchdog）

针对"启动 systemd 服务"这类中风险操作，设计了一个从**客户端（你的电脑）主动探测**的看门狗机制，而不是依赖服务器自己监控自己（因为如果服务器网络真的坏了，服务器自己的监控脚本也没用）：

1. 在服务器上执行任何可能有风险的变更前，先记录当前状态（比如"变更前 systemctl list-units 快照"、"变更前 ss -tlnp 快照"）
2. 执行变更（比如 `systemctl start opennofrp-server`）
3. 从**本地 Windows 电脑**，立即通过已有的 SSH 连接执行验证命令（而不是等新建立的连接，因为如果新组件破坏了网络，新连接根本建立不起来，但已有连接可能还活着）
4. 如果 N 秒内验证失败（现有 SSH 会话卡死、或验证命令超时），立即在**同一个已有 SSH 会话**里执行回滚命令（比如 `systemctl stop opennofrp-server && systemctl disable opennofrp-server`）
5. 全程不新建 SSH 连接做验证——因为一旦现有网络配置被破坏，新连接必然失败，只有复用当前存活的连接才能保证还能发出"救命"指令

**关键原则：任何一步操作后，必须先用当前存活的 SSH 会话验证，再进行下一步。绝不批量执行多个有风险的操作后再统一检查。**

## 五、卸载安全清单

卸载脚本执行时，只允许删除以下内容（白名单机制，而非"删除一切看起来相关的东西"）：

**服务器端（Linux）**：
- `/etc/systemd/system/opennofrp-server.service`（且必须先 `systemctl stop` + `systemctl disable`）
- `/opt/opennofrp/`（整个安装目录，仅限本项目专用路径，不与 `/opt` 下任何现有软件目录同名）
- 不删除、不修改任何其他 `/etc/systemd/system/*.service` 文件
- 不执行 `iptables`/`nft`/`ip route` 任何修改命令

**Windows 客户端**：
- 停止并删除注册的 Windows 服务（服务名固定为 `OpenNoFrpClient`，避免误删同名的其他服务）
- 删除安装目录（默认 `C:\Program Files\OpenNoFrp\`）
- 不修改任何系统防火墙规则（如果客户端需要入站规则，安装时会创建一条命名规则 `OpenNoFrp-Inbound`，卸载时精确删除这一条，不做批量清理）

## 六、当前进度声明

截至本文档编写时，**尚未对服务器执行任何写入或变更操作**。所有服务器端信息均来自此前的只读调查（`df`、`ip`、`nft list ruleset`、`cat frpc.toml` 等），未修改任何配置。后续每一步涉及服务器的操作都会先展示计划、经你确认后再执行，并遵循本文档的验证流程。
