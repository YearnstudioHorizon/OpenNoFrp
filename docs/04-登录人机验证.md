# 登录人机验证

进入管理面板的「安全设置」选择验证方式并保存。默认关闭，以兼容已有部署。设置保存在服务器 SQLite 数据库，重启后保留。此功能保护管理面板登录；客户端控制连接和 Bearer API 令牌不使用浏览器验证码。

## 内建验证

选择「内建图片验证码」即可，无需部署其他服务。登录时输入图片中的五位数字，可点击「换一张」。三分钟过期，每次提交都会消耗验证码，登录失败后需要重新填写。它提供基础的自动化防护；对抗更复杂的机器人可选择 fCaptcha 或极验。

## WebDecoy/FCaptcha

填写自部署实例的根地址、Site Key 和服务端 Secret，例如 `https://captcha.example.com`。实例可以使用带路径前缀的地址。浏览器加载 `<实例地址>/fcaptcha.js` 并访问实例 API，OpenNoFrp 服务器通过 `<实例地址>/api/token/verify` 校验 token；要求验证通过、风险分数低于 `0.5`，并核对签名中的 Site Key、面板域名和勾选模式的空 action。使用支持这些返回字段的现行版本。

浏览器和 OpenNoFrp 服务器都需要能访问实例。HTTPS 面板使用 HTTPS 实例，避免浏览器拦截混合内容。根据实例部署方式配置 Site Key、面板域名及跨域允许来源。面板配置的 `base_url` 应与浏览器访问域名一致；未设置时按当前请求的 Host 校验。Secret 填写实例的 `FCAPTCHA_VERIFY_SECRET`（未单独设置时使用 `FCAPTCHA_SECRET`），不应填写到网页或 Site Key 字段。

参考：[项目与部署文档](https://github.com/WebDecoy/FCaptcha)、[安装说明](https://github.com/WebDecoy/FCaptcha/blob/main/INSTALLATION.md)。

## GEETEST 极验 v4

从极验后台获取 Captcha ID 与 Captcha Key，配置面板域名，在安全设置填写并保存。使用官方 v4 浏览器组件，服务器通过 HTTPS 调用二次校验接口，用 Captcha Key 对 `lot_number` 生成 HMAC-SHA256 签名。浏览器提交的 Captcha ID 不会覆盖服务器配置。

参考：[Web 接入 API](https://docs.geetest.com/gt4/apirefer/api/web)、[服务端二次校验](https://docs.geetest.com/gt4/apirefer/api/server)。

## 密钥、失败和恢复

已配置的密钥不会回显，留空保存时保留已有密钥。切换验证方式会保留其他提供方配置。外部请求有八秒超时；网络失败、非成功响应或验证未通过时，不放行登录。验证码失败也计入登录失败次数。外部 token 在本进程内禁止重复使用，内建验证码与浏览器 Cookie 关联且只可使用一次。

配置前可以保留一个已登录页面，保存后当前会话仍能修改设置。如果第三方实例无法使用或密钥配置错误导致无法登录，在服务器本机执行：

```sh
opennofrp-server reset-captcha -c /etc/opennofrp/server.toml
```

该命令读取对应配置的数据库，将登录验证关闭，保留管理员密码与提供方配置，无需重启服务。需要具备服务器配置和数据库的访问权限；没有远程免登录重置接口。进入面板修正设置后，再次开启验证。
